# Blossom Architecture Design Audit

**Date:** 2026-11-23  
**Status:** Source-verified architectural review and remediation roadmap  
**Scope:** Control plane (`app/`, `packages/*`), multi-runtime realtime stack (Cloudflare Durable Objects vs. Nitro/Redis), Rust data-plane supervisor (`server-agent/`), cross-language contracts, database persistence, background scheduling, and frontend/SSR engineering gates.

---

## Executive Summary

Blossom demonstrates strong security and consistency fundamentals: strict physical separation between admin server functions and the per-server agent surface, envelope-encrypted certificate material (`CERTIFICATE_MASTER_KEY`), monotonic publish-gate sequencing, database-fenced WebSocket sessions, and single-statement idempotent traffic ledgers.

Its core architectural problem is **orthogonal compatibility matrix explosion combined with unretired transitional dual stacks**:

- **Control plane:** 3 deployment targets (`cloudflare`, `node`, `vercel`) × 2 PostgreSQL drivers (`node-postgres`, `neon-http`) × 3 mutation/API surfaces (TanStack Server Functions, MCP tools, REST/oRPC routes) × 2 agent wire protocols (`v1`, `blossom-agent.v2`).
- **Server agent (`server-agent/`):** 2 wire/control loops (`legacy` HTTP+WS v1 vs. `v2` WS-only) × 2 credential models (static token vs. OAuth `client_credentials`) × 2 supervision/update/metering stacks (`processkit`/Docker vs. privilege-separated `native` systemd).

Maintaining every combination simultaneously without shared state-machine reducers or automated cross-language contract generation has pushed several subsystems past their abstraction limits, producing silent broken paths on primary deployment targets and hard scalability ceilings.

## 1. Multi-Runtime Split & Duplicated Realtime Stacks

### 1.1 Divergent Build-Time Adapter Architecture (~5,930 LOC Split)

[`app/vite.config.ts`](../../../app/vite.config.ts) (`lines 65-106`) swaps runtime implementations at bundle time via `DEPLOY_TARGET` (`cloudflare`, `vercel`, `node`), maintaining two separate stateful WebSocket stacks:

- **Nitro + Redis stack (~2,571 LOC):** [`realtime-hub.ts`](../../../app/src/lib/realtime-hub.ts) (`1,865` lines), [`pty-relay.ts`](../../../app/src/lib/pty-relay.ts) (`341` lines), [`logs-relay.nitro.ts`](../../../app/src/lib/logs-relay.nitro.ts) (`232` lines), and [`admin-metrics-relay.ts`](../../../app/src/lib/admin-metrics-relay.ts) (`133` lines).
- **Cloudflare Durable Object stack (~3,360 LOC):** [`agent-session.cloudflare.ts`](../../../app/src/durable-objects/agent-session.cloudflare.ts) (`1,420` lines), [`pty-session.cloudflare.ts`](../../../app/src/durable-objects/pty-session.cloudflare.ts) (`825` lines), [`logs-session.cloudflare.ts`](../../../app/src/durable-objects/logs-session.cloudflare.ts) (`618` lines), [`realtime-hub.cloudflare.ts`](../../../app/src/lib/realtime-hub.cloudflare.ts) (`363` lines), [`pty-relay.cloudflare.ts`](../../../app/src/lib/pty-relay.cloudflare.ts) (`72` lines), and [`admin-metrics-relay.cloudflare.ts`](../../../app/src/lib/admin-metrics-relay.cloudflare.ts) (`62` lines).

Adapter boundaries follow three inconsistent patterns:

1. Vite path aliases (`@/lib/database-connection`, `@/lib/realtime-hub`, `@/lib/pty-relay`, `@/lib/admin-metrics-relay`, `@/durable-objects/agent-session`), where [`realtime-hub.ts`](../../../app/src/lib/realtime-hub.ts) (`line 1863`) leaks `NitroRealtimeHub` concrete methods rather than returning the narrow `RealtimeHub` interface;
2. A `.nitro.ts` suffix with no Vite alias for log streaming (`logs-relay.nitro.ts` vs. `logs-session.cloudflare.ts`), routed through `RealtimeHub.acceptAdminLogs`;
3. `AgentSessionDO` multiplexing **five distinct WebSocket attachment schemas** (`V1AgentSessionAttachment`, `V2AgentSessionAttachment`, `PtySocketAttachment`, `LogSocketAttachment`, `MetricsAdminAttachment`) inside a single `ctx.getWebSockets()` set while manually serializing ~25 custom `x-blossom-*` internal HTTP headers between the Worker and the Durable Object ([`realtime-hub-types.ts`](../../../app/src/lib/realtime-hub-types.ts), `lines 140-160`). Meanwhile, `app/tsconfig.json` and [`app/vitest.config.ts`](../../../app/vitest.config.ts) (`lines 8-16`) resolve `@/lib/*` to the Nitro modules by default.

### 1.2 Concrete Failures Produced by the Runtime Split

1. **Cloudflare `AgentSessionDO` drops v2 session `capabilities` and `snapshotGeneration` across frames:**
   In [`agent-session.cloudflare.ts`](../../../app/src/durable-objects/agent-session.cloudflare.ts) (`lines 1295-1366`), `handleV2Message` constructs a brand-new `openAgentWsV2Session(...)` closure on every inbound WebSocket message, restoring only `welcomed` and `pending` from `V2AgentSessionAttachment` (`lines 110-122`). Closure variables `capabilities` and `snapshotGeneration` ([`agent-ws-v2-session.ts`](../../../app/src/lib/agent-ws-v2-session.ts), `lines 383-384`) reset to `[]` and `0` on every frame after `hello`:
   - Every `config.get` on a managed-networking server passes `agentCapabilities: []` to `buildAgentDesiredState` ([`agent-desired-state.ts`](../../../app/src/orpc/proxy/agent-desired-state.ts), `lines 205-216`), throwing `ManagedCompileError("unsupported_agent")` and failing closed with `config.snapshot.error`.
   - Every `link_probe.result` hits `if (!capabilities.includes(MANAGED_LINK_PROBE_CAPABILITY)) return;` ([`agent-ws-v2-session.ts`](../../../app/src/lib/agent-ws-v2-session.ts), `line 731`) and is silently discarded.
   - Concurrent `config.get` supersession (`snapshotGeneration`) is defeated because every frame starts back at `0`.

2. **Uncoordinated Durable Object `setAlarm()` / `deleteAlarm()` collisions:**
   `AgentSessionDO` has one `ctx.storage` alarm slot shared across v2 OAuth lease checks, PTY 30-second authority checks, and Logs 10-second search/context timeouts:
   - Closing the last admin Logs socket invokes `scheduleLogAlarm` → `ctx.storage.deleteAlarm()` ([`logs-session.cloudflare.ts`](../../../app/src/durable-objects/logs-session.cloudflare.ts), `line 255`) and returns early in `webSocketClose` ([`agent-session.cloudflare.ts`](../../../app/src/durable-objects/agent-session.cloudflare.ts), `line 1116`), **erasing active PTY revalidation and v2 OAuth expiry alarms**.
   - During `alarm()` (`lines 703-755`), `revalidatePtySockets` re-arms the 30s PTY alarm ([`pty-session.cloudflare.ts`](../../../app/src/durable-objects/pty-session.cloudflare.ts), `line 745`), which `revalidateLogSockets` and `scheduleV2Alarm` (`line 694`) immediately delete when no log or v2 sockets are present—so v1 PTY sessions are revalidated once and never checked again.
   - Every inbound v2 frame calls `this.scheduleV2Alarm()` (`line 1367`), pushing any pending 10-second log search timeout alarm out to 30 seconds.

3. **Unbounded live telemetry leak, per-frame DB revalidation, and per-frame `pg.Pool` churn:**
   - `AgentSessionDO.stopMetricsSampling()` ([`agent-session.cloudflare.ts`](../../../app/src/durable-objects/agent-session.cloudflare.ts), `lines 857-864`) clears `this.metricsSubscriptionId` without sending `telemetry.unsubscribe` to the v2 agent. Once an administrator views a server's live metrics once and closes the tab, the agent continues sending 2-second `telemetry.sample` frames indefinitely, preventing DO hibernation.
   - `openAgentWsV2Session.handleText()` ([`agent-ws-v2-session.ts`](../../../app/src/lib/agent-ws-v2-session.ts), `line 874`) runs `await revalidate()` (`SELECT * FROM server` plus 3-table OAuth `EXISTS` subqueries) **before parsing every single inbound frame**—including `pty.data` keystrokes, 500ms `logs.batch` frames, and 2s `telemetry.sample` frames. Inside `AgentSessionDO`, `this.withDatabase(...)` (`lines 306-327, 1293`) creates a new `drizzle(connectionString)` (`new pg.Pool`) and awaits `$client.end()` on every frame (bypassing `@blossom/database/server` and hardcoding `node-postgres`).
   - Additional Cloudflare regressions: `CloudflareRealtimeHub.inspectTelemetry` ([`realtime-hub.cloudflare.ts`](../../../app/src/lib/realtime-hub.cloudflare.ts), `line 232`) hardcodes `return null` whenever `sessionId !== null`, breaking the UI port/interface **Inspect** button for all default v2 agents; [`admin-metrics-route.ts`](../../../app/src/lib/admin-metrics-route.ts) (`lines 35-38`) omits `query: { disableRefresh: true }` on `getSession()`, which breaks `101` WebSocket upgrades on `workerd` during rolling cookie refreshes; and `handleAcmeResult` inside `AgentSessionDO` calls `notifyAgentConfigChanged` ([`certificate-issuance.ts`](../../../app/src/lib/certificate-issuance.ts), `lines 724, 937-940`), touching the request-scoped `@/db` facade (`getRequest()`) inside a DO callback and self-fetching `/internal/notify` re-entrantly.

4. **Broken cross-instance Redis backplane for v2 on Node and Vercel:**
   In [`realtime-hub.ts`](../../../app/src/lib/realtime-hub.ts) (`lines 666-687`), `NitroRealtimeHub.publishV2()` checks `const agentSessionId = this.currentV2Sessions.get(serverId)?.sessionId; if (!agentSessionId) return;` **before** publishing to `this.backplane`. Because `this.currentV2Sessions` is populated only on the instance holding the live agent WebSocket, any mutation or admin viewer hitting another Node replica or Vercel function instance returns immediately and never publishes to Redis. Even if fixed:
   - `RedisBackplane` (`lines 144-180`) opens 2 persistent `ioredis` TCP connections per instance and broadcasts all frames (terminal bytes, log batches, 2s metrics across all servers) over a **single global Redis Pub/Sub channel** (`blossom:agent-ws:v1`) with swallowed connection errors (`() => undefined`) and fire-and-forget semantics.
   - Deterministic `live-${context.sessionId}` subscription IDs (`line 704`) collide across instances: the first instance whose viewer closes sends `telemetry.unsubscribe`, killing live metrics for viewers connected to other instances.
   - [`app/vercel.json`](../../../app/vercel.json) configures neither `maxDuration` nor `crons`, making the `vercel` target structurally incompatible with long-lived stateful agent and admin relays when `REDIS_URL` is optional.

5. **Pre-upgrade session fence race and inconsistent SQL fence predicates:**
   - On Cloudflare, the Worker updates `server.wsSessionId` in PostgreSQL ([`realtime-hub.cloudflare.ts`](../../../app/src/lib/realtime-hub.cloudflare.ts), `line 124`) before forwarding `/internal/connect` to `AgentSessionDO` (`line 161`); out-of-order concurrent upgrades can cause the older upgrade to evict the newer socket inside the DO while PostgreSQL fences out the older socket, killing both connections.
   - Core v2 writes in [`query/agent.ts`](../../../app/src/query/agent.ts) (`lines 291-332, 945-950`) fence on `ws_session_id` **and** `currentAgentCredentialSql()` (checking OAuth expiry/revocation), whereas [`server-metric-store.ts`](../../../app/src/query/server-metric-store.ts) (`lines 99-106`), [`managed-rollout-write.ts`](../../../app/src/query/managed-rollout-write.ts) (`lines 536-548`), and [`logs-authority.ts`](../../../app/src/lib/logs-authority.ts) (`line 116`) check only `ws_session_id = sessionId`.

## 2. Control-Plane / Data-Plane Coupling & Blast Radius

### 2.1 `O(inbounds × active_subscriptions)` Compilation, N+1 Queries, and Hard `8 MiB` Wire Limit

Blossom compiles dynamic subscriber authorization and credentials directly into static `sing-box` `inbounds[].users` arrays ([`singbox.ts`](../../../app/src/orpc/proxy/singbox.ts), `lines 135-141`):

- **Per-node N+1 SQL queries:** [`agent-desired-state.ts`](../../../app/src/orpc/proxy/agent-desired-state.ts) (`lines 74-84`) loops over every enabled node on a server and runs `getNodeActiveSubscriptions(node.id)` ([`subscription-access.ts`](../../../app/src/query/subscription-access.ts), `lines 306-346`, a 4-table join across `node_group`, `plan_group`, `subscription`, and `user`) once per node. Cached configuration identifiers expire at least every `AGENT_DESIRED_CONFIG_MAX_AGE_MS = 120_000` ms (`line 42`), forcing full recompilation, Zod `Configuration.parse`, and canonical key-sorted SHA-256 hashing.
- **Hard `8 MiB` snapshot cliff:** `MAX_SNAPSHOT_BYTES` is capped at `8 MiB` ([`packages/contracts/src/agent-ws-v2.ts`](../../../packages/contracts/src/agent-ws-v2.ts) `line 84`, [`ws/v2/codec.rs`](../../../server-agent/src/ws/v2/codec.rs) `line 35`, [`config_managed.rs`](../../../server-agent/src/config_managed.rs) `line 46`). At ~130–170 JSON bytes per user entry, a server with **20 inbounds × 5,000 active subscriptions** generates **100,000 user entries (~14–17 MiB)**, permanently wedging updates with `SnapshotTooLarge`.

### 2.2 Process-Wide `sing-box` Restarts on Single-User Churn & 11-Second Serialized Probation

- **Zero incremental user hot-reload:** Any new subscription purchase, single-user credential rotation, plan/status update, subscription expiry, quota exhaustion, or temporary 15-minute `sing-box` debug log override ([`legacy.rs`](../../../server-agent/src/legacy.rs), `lines 560-610`) produces a new candidate config and **terminates and restarts the entire `sing-box` process** (`SingBoxManager::shutdown` + `start` in [`legacy.rs`](../../../server-agent/src/legacy.rs) `lines 1011-1025`, or `systemctl restart blossom-sing-box.service` in [`service/lifecycle.rs`](../../../server-agent/src/service/lifecycle.rs) `lines 122-125`). Every single-user event severs all active TCP, UDP, QUIC/Hysteria2/TUIC, and multiplexed streams for every user on that host.
- **Inline 11-second probation blocks the core loop:** `DEFAULT_RUNTIME_PROBATION_SECS = 11` ([`cli.rs`](../../../server-agent/src/cli.rs) `line 205`, [`legacy.rs`](../../../server-agent/src/legacy.rs) `lines 47, 1048`) is awaited inline inside the main `tokio::select!` supervision loop ([`agent_v2.rs`](../../../server-agent/src/agent_v2.rs), `lines 374-386`). During probation, the agent core cannot process PTY frames, ACME DNS ACKs, link probes, or subsequent snapshots, capping apply throughput at **~5 applies/minute** and stalling subscription publish-gate convergence during normal user signup/expiry bursts.
- **Delayed quota enforcement:** When [`recordAgentTraffic`](../../../app/src/query/agent.ts) (`lines 1508-1517`) pushes `traffic_used_bytes` past `traffic_quota_bytes`, it neither invalidates `server.desiredConfigRevision` nor dispatches `config.notify`, leaving exhausted credentials active until `desiredConfigValidUntil` expires and `sing-box` restarts.

### 2.3 Permanent `SecretRedactor` Blackout Above ~600–1,000 Subscriptions

[`server-agent/src/logs/text.rs`](../../../server-agent/src/logs/text.rs) (`line 24`) caps `MAX_SECRET_FORMS = 4096`. Each subscription contributes raw, JSON-escaped, and URL-encoded forms for its UUID and base64 password (~4–7 forms per user, doubled across `active.json` and `candidate.json` in [`config.rs`](../../../server-agent/src/config.rs) `lines 482-484`). Once total forms exceed `4,096` (~585–1,024 subscriptions), `overflowed = true` latches **for the entire remaining lifetime of the agent process** (`lines 105-107, 141-144`), replacing 100% of retained log lines and preflight failure diagnostics with `"[REDACTED]"`. Below `4,096`, `replace_spans` (`lines 348-356`) runs up to 4,096 linear `str::match_indices` scans per log line instead of an Aho-Corasick automaton.

### 2.4 Hardcoded `tls://8.8.8.8` DNS Breaks Restricted-Network Relay Topologies

[`singbox.ts`](../../../app/src/orpc/proxy/singbox.ts) (`lines 91-93`) hardcodes `{ tag: "google", type: "tls", server: "8.8.8.8" }` as the sole DNS server on every host, and [`managed-singbox.ts`](../../../app/src/orpc/proxy/managed-singbox.ts) (`lines 229-231`) pins every hostname-based peer outbound to `domain_resolver: "google"` over direct egress. On entry servers inside Mainland China—the primary target for A→B managed relay topologies—direct DoT (`8.8.8.8:853`) is blocked, preventing hostname-based peer links from resolving or bootstrapping.

## 3. `server-agent/` Dual-Runtime Debt & Broken Native Systemd Paths

### 3.1 Inverted `agent_v2` → `legacy` Coupling & Quadruple JSON Envelope Shims

Although `blossom-agent.v2` is the default runtime, [`legacy.rs`](../../../server-agent/src/legacy.rs) (`2,378` lines) was never decomposed into transport-neutral domain modules:

- [`main.rs`](../../../server-agent/src/main.rs) (`lines 43-49`) re-exports 18 runtime functions and types out of `legacy.rs` into [`agent_v2.rs`](../../../server-agent/src/agent_v2.rs) (`lines 66-71`)—including `apply_native_fetched` (`legacy.rs`, `lines 686-894`), even though `--native-service-control` is forbidden in legacy mode ([`cli.rs`](../../../server-agent/src/cli.rs), `lines 379-383`).
- `agent_v2.rs` (`line 142`) instantiates a dummy OpenAPI HTTP client (`new_client(&startup.url, "v2-does-not-use-http")`) solely to satisfy `ConfigManager`'s struct field.
- Inbound and outbound PTY, ACME, and `update.status` frames on v2 undergo **four JSON serialization/deserialization passes** (`v2` struct → `serde_json::Value` → `v1` `AgentWsFrame` → `legacy.rs` private struct, and the reverse in [`ws/v2/session.rs`](../../../server-agent/src/ws/v2/session.rs) `lines 706-718, 1094-1109, 1165-1193`).

### 3.2 Critical Breaks in the Native Systemd & Supply-Chain Matrix

1. **Privilege separation breaks all managed TLS certificates, peer CAs, and `.srs` rule-sets:**
   [`agent-installer-template.sh`](../../../app/src/lib/agent-installer-template.sh) (`lines 21-25, 526-549, 614-616`) runs `blossom-agent.service` as `blossom-agent` (`STATE_DIR=/var/lib/blossom-agent`, mode `0700`) and `blossom-sing-box.service` as `blossom-runtime` (`ProtectSystem=strict`). [`certificate.rs`](../../../server-agent/src/certificate.rs) (`lines 69, 524-561`) and [`config_managed.rs`](../../../server-agent/src/config_managed.rs) (`lines 703-789`) stage PEMs and `.srs` files inside `/var/lib/blossom-agent/...` and write those paths into `candidate.json`. Preflight `sing-box check` runs as `blossom-agent` and succeeds, [`Promoter::stage_config`](../../../server-agent/src/service/promote.rs) (`lines 285-297, 384-408`) copies **only** `config.json` into `/var/lib/blossom-service-control/`, and `blossom-sing-box.service` crashes on startup with `EACCES` (`permission denied`) whenever any certificate or rule-set is referenced.
2. **Rogue `processkit` `sing-box` child spawned inside `blossom-agent.service`:**
   [`agent_v2.rs`](../../../server-agent/src/agent_v2.rs) (`lines 79-88`) unconditionally advertises `"log-policy-v1"`, `"logs-tail-v1"`, and `"logs-search-v1"` in native mode, drops incoming `log.policy.snapshot` jobs (even agent-only tracing filter changes) while reporting `error: None` (`lines 473-486, 744-776`), returns empty `sing-box` logs (no `journald` reader), and runs `log_policy_maintenance` every 5 seconds (`lines 599-608`) **without checking `if native.is_none()`**. If a persisted `sing-box` log override expires, [`legacy.rs`](../../../server-agent/src/legacy.rs) (`line 589`) calls `SingBoxManager::start(...)`, spawning a competing `sing-box` process inside `blossom-agent.service`.
3. **100% of `naive`, `socks`, and `http` traffic is dropped unbilled in native metering:**
   [`singbox-users.ts`](../../../app/src/orpc/proxy/singbox-users.ts) (`lines 96-100`) sets `username: sub.id` instead of `encodeTrafficUser(nodeId, sub.id)` for `username`-keyed protocols. Native [`SubscriberIdentity::decode`](../../../server-agent/src/metering/filter.rs) (`lines 159-165, 199-202`) requires the `"blz.1."` prefix and rejects bare subscription IDs as `MalformedIdentity`, discarding all usage for those protocols.
4. **Unfinished installer/promoter vs. mutable root Docker bootstrap:**
   - [`agent-installer-releases.ts`](../../../app/src/lib/agent-installer-releases.ts) (`line 12`) ships `APPROVED_AGENT_RELEASES = []`, causing systemd installer downloads to fail with `no_approved_release`; `SignedReleaseManifest` promotion (`ControlClient::promote` in [`service/control.rs`](../../../server-agent/src/service/control.rs) `line 437`) is `#[allow(dead_code)]` with no CI manifest signing step, [`Helper::promote`](../../../server-agent/src/service/helper.rs) (`lines 294-302`) omits `self.operation.lock().await`, [`cli.rs`](../../../server-agent/src/cli.rs) lacks a runtime guard rejecting `--native-service-control` + `--pty-enabled` (exposing `SO_PEERCRED`-trusted `control.sock` to the PTY UID), [`agent-installer-script.ts`](../../../app/src/lib/agent-installer-script.ts) (`line 79`) checks `"pty-v1"` instead of `"pty-v2"`, and [`agent-installer-template.sh`](../../../app/src/lib/agent-installer-template.sh) (`line 357`) checks nonexistent `$STATE_DIR/config.json` instead of `active.json`.
   - Conversely, [`server-agent/Dockerfile`](../../../server-agent/Dockerfile) (`lines 10-31`) runs as `root` on floating `alpine:latest` (permanently disabling PTY in Docker) and ships **neither** `server-agent` nor `sing-box` inside the version-tagged GHCR image—instead downloading unpinned `latest` GitHub releases at container boot ([`entrypoint.sh`](../../../server-agent/scripts/entrypoint.sh), `lines 39-40, 148-246`) verified only against the same GitHub API JSON response's `digest`.

## 4. Dual Database Driver Compromises (`neon-http` vs. `node-postgres`)

Supporting `neon-http` (stateless HTTP queries with no interactive `BEGIN`/`COMMIT` transactions) alongside `node-postgres` ([`packages/database/src/server.ts`](../../../packages/database/src/server.ts), `lines 21-28`) imposes severe structural costs across `app/src/query/`:

1. **Multi-thousand-line raw CTE monoliths:** Achieving atomicity without `db.transaction()` required encoding complex multi-table state machines into enormous single-statement data-modifying CTEs—e.g., [`managed-topology-write.ts`](../../../app/src/query/managed-topology-write.ts) (`3,016` lines), [`managed-rollout-write.ts`](../../../app/src/query/managed-rollout-write.ts) (`2,053` lines), and [`group-membership-write.ts`](../../../app/src/query/group-membership-write.ts) (`1,227` lines).
2. **Broken atomicity and publish-gate violations where CTEs were not written:**
   - [`nodes.ts`](../../../app/src/query/nodes.ts) (`lines 225-243`) falls back on `neon-http` to sequential non-transactional writes with partial manual compensation.
   - [`mcp-tools.ts`](../../../app/src/query/mcp-tools.ts) (`lines 202-276, 308-343, 413-455, 601-695`) executes multi-step reads, entity mutations, and `recordConfigChange` calls **outside any transaction even on `node-postgres`**. If `recordConfigChange` fails after `writeLegacySubscriberNode` commits, an enabled node becomes immediately visible on `/api/sub/$token` before any agent applies it.
   - [`runtime-migrations.ts`](../../../app/src/lib/runtime-migrations.ts) (`lines 28-35, 164-171, 206-208`) eagerly bundles every historical `app/drizzle/*/migration.sql` file into the production Worker bundle and, when interactive transactions are unavailable, executes migration statements one-by-one without `pg_advisory_xact_lock` or rollback safety.
3. **Binary blobs stored as Base64 in PostgreSQL OLTP rows:** [`managed-network-schema.ts`](../../../app/src/db/managed-network-schema.ts) (`lines 228-253`) stores up to `512 KiB` binary `.srs` rule-set assets as Base64 text in `managed_rule_set_asset.content_base64`, which [`managed-singbox.ts`](../../../app/src/orpc/proxy/managed-singbox.ts) (`lines 395-408`) decodes and SHA-256 hashes in JS memory during compilation.

## 5. API Surface Fragmentation, Dual-Compiler Drift & Contract Inversion

### 5.1 Missing Application Service Layer Across Server Functions, MCP, and Routes

Admin mutations are implemented separately in `app/src/query/*.ts` (TanStack Server Functions) and [`app/src/query/mcp-tools.ts`](../../../app/src/query/mcp-tools.ts) rather than delegating to shared domain services:

- `createNode` / `updateNode` in [`nodes.ts`](../../../app/src/query/nodes.ts) (`line 445`) strip raw X.509 fields via `withoutNodeTlsMaterial` and validate `certificateId` / `tlsServerName`, whereas `createNodeMCP` / `updateNodeMCP` in [`mcp-tools.ts`](../../../app/src/query/mcp-tools.ts) (`lines 321, 393`) omit `withoutNodeTlsMaterial` and ignore managed certificate bindings. MCP Zod input schemas are also duplicated between `orpc/mcp/context.ts` and [`routes/api/mcp.ts`](../../../app/src/routes/api/mcp.ts), which rebuilds its MCP handler on every HTTP request.
- [`admin-audit.test.ts`](../../../app/src/lib/admin-audit.test.ts) (`lines 88-121`) structurally enforces `adminAudit(...)` on `POST` server functions, but **neither verifies `ensureAdmin()` on `POST` handlers nor checks `GET` server functions at all**.
- Dead/exposed scaffolding: [`app/src/orpc/client.ts`](../../../app/src/orpc/client.ts) is unused; [`app/src/routes/api/$.ts`](../../../app/src/routes/api/$.ts) (`lines 19, 31-97`) mounts `OpenAPIReferencePlugin` unauthenticated in production with a prefilled `"default-token"` and leaks template `TodoSchema` into [`server-agent/openapi/spec.json`](../../../server-agent/openapi/spec.json) (`types::Todo`).

### 5.2 Sing-Box Inbound vs. Clash Outbound Dual-Compiler Drift & Single-Format Lock-In

- **VLESS + Reality loses SNI on both server and client:** `withoutNodeTlsMaterial` ([`sing-box-registry.ts`](../../../app/src/orpc/proxy/sing-box-registry.ts), `lines 195-203`) unconditionally deletes `settings.tls.server_name` on save. [`singbox.ts`](../../../app/src/orpc/proxy/singbox.ts) (`lines 106-132`) only re-injects `node.tlsServerName` when `usesManagedCertificate` is true (`!isNodeRealityEnabled`), omitting `server_name` on Reality inbounds. On the client side, [`clash-proxies.ts`](../../../app/src/lib/clash-proxies.ts) (`lines 343-346`) reads `tlsObj.server_name` from `node.settings` (deleted on write) rather than `node.tlsServerName`, emitting Reality Clash proxies with no `servername` / `sni`.
- **Uncached Clash-only subscription delivery:** [`routes/api/sub/$token.ts`](../../../app/src/routes/api/sub/$token.ts) (`lines 62-151`) emits only Clash Meta YAML (no native `sing-box` client JSON or universal URI profiles) and executes 4–7 sequential DB queries, synchronous `await recordAccessLog(...)` insertion, and full YAML serialization on every pull without ETag or caching.

### 5.3 Inverted Cross-Language Contract Generation & Thin Workspace Boundaries

- **Codegen exists only for legacy HTTP, not `blossom-agent.v2`:** Regenerating [`server-agent/openapi/spec.json`](../../../server-agent/openapi/spec.json) via `pnpm --filter @blossom/app agent:spec` ([`app/package.json`](../../../app/package.json), `line 21`) requires a live `localhost:3000` dev server (so CI never checks spec drift), down-converts OAS 3.1 to 3.0 imperfectly (patched at compile time in [`server-agent/build.rs`](../../../server-agent/build.rs), `lines 59-86`), and causes [`ConfigManager::compile_snapshot`](../../../server-agent/src/config.rs) (`lines 768-806`) to parse every incoming v2 snapshot **three times**.
- **Manual TS Zod ↔ Rust `serde` drift self-rejects non-ASCII frames:** Over `3,350` lines of Zod schemas in `packages/contracts/src/*.ts` and `2,459` lines of Rust codecs in [`ws/v2/codec.rs`](../../../server-agent/src/ws/v2/codec.rs) are synchronized by hand. TypeScript `.max(N)` counts UTF-16 code units while `codec.rs`'s `bounded()` (`lines 441-443`) counts UTF-8 bytes. [`agent_v2.rs`](../../../server-agent/src/agent_v2.rs) (`line 763`) truncates `LogPolicyAck.error` with `.chars().take(512)` and [`legacy.rs`](../../../server-agent/src/legacy.rs) (`line 1625`) truncates `PtyExit.detail` with `.chars().take(256)`—so non-ASCII error messages exceed 512 / 256 UTF-8 bytes and are **rejected and dropped by the agent's own outbound validator** (`codec.rs`, `lines 844, 1929`).
- **Incomplete workspace package boundaries:** [`packages/domain/package.json`](../../../packages/domain/package.json) and [`packages/contracts/package.json`](../../../packages/contracts/package.json) define no `tsconfig.json`, `build`, or `test` scripts, while Drizzle schemas (`app/src/db/*-schema.ts`) and core proxy schemas (`app/src/orpc/proxy/schema.ts`) remain inside `app/`.

## 8. Prioritized Architectural Remediation Roadmap

### Phase 0 — Stop-the-Bleed Correctness Fixes (Immediate)

1. **Cloudflare `AgentSessionDO` state & alarm coordinator:** Persist `capabilities` (and `snapshotGeneration`) in `V2AgentSessionAttachment`; introduce a single earliest-deadline alarm multiplexer across v2 leases, PTY revalidation, and log search timeouts; send `telemetry.unsubscribe` in `stopMetricsSampling()`; move session DB revalidation off the per-frame hot path onto a bounded interval + revocation push; reuse a DO-scoped `pg.Pool` instead of creating/ending one per frame; fix `inspectTelemetry` for v2 and add `disableRefresh: true` in `admin-metrics-route.ts`.
2. **Multi-instance Redis backplane:** Remove the local `this.currentV2Sessions` early return in `NitroRealtimeHub.publishV2()` and shard Redis channels per server (`blossom:server:<id>`).
3. **Native systemd blockers:** Stage certificates, peer CAs, and `.srs` files into `blossom-runtime`-readable artifact directories under `/var/lib/blossom-service-control/` via `service-control-helper` and rewrite `candidate.json` paths; guard `log_policy_maintenance` when `native.is_some()`; reject `--native-service-control` + `--pty-enabled` in `cli.rs`; acquire `self.operation.lock().await` in `Helper::promote`; and change `username: sub.id` to `encodeTrafficUser(nodeId, sub.id)` in `singbox-users.ts`.
4. **Protocol & DNS fixes:** Inject `node.tlsServerName` for Reality inbounds in `singbox.ts` and read `node.tlsServerName` in `clash-proxies.ts`; make server bootstrap/peer DNS configurable instead of hardcoding `tls://8.8.8.8`; align UTF-8 vs. scalar truncation in `LogPolicyAck` and `PtyExit`.

### Phase 1 — Architectural Simplification & Matrix Reduction

1. **Standardize on `node-postgres` and retire `neon-http`:** Neon natively supports pooled `pg` connections and Cloudflare Hyperdrive. Dropping `neon-http` restores interactive `db.transaction()` everywhere, allowing multi-thousand-line raw CTEs and fragile manual compensations to be replaced by standard transactional domain services.
2. **Consolidate deployment targets & share pure session reducers:** Commit to **Node (Docker) + Cloudflare Workers** as tier-1 targets (dropping the half-configured Vercel WebSocket target), and extract pure transport-agnostic state machines for Agent v2, PTY, and Metrics (matching `logs-relay.ts`) so Nitro and `AgentSessionDO` remain thin I/O adapters.
3. **Introduce a unified Application Service Layer & server-function middleware:** Route both TanStack Server Functions and MCP tools through shared transactional services; enforce `ensureAdmin()` via composable middleware (`adminQuery` / `adminMutation`) backed by a structural test covering both `GET` and `POST`; gate `/api/spec.json` and remove `TodoSchema` / `orpc/client.ts`.
4. **Retire `legacy.rs` / HTTP `progenitor` codegen & bake immutable Docker images:** Extract domain modules out of `legacy.rs`, generate/validate `blossom-agent.v2` schemas directly from `@blossom/contracts` offline in CI (alongside `tsc --noEmit` and expanded `oxlint` rules), and ship version-pinned binaries inside `ghcr.io/.../server-agent` as a non-root user.

### Phase 2 — Data-Plane Decoupling & Scale Hardening

1. **Batch compilation & externalize binary assets:** Replace per-node `getNodeActiveSubscriptions` loops with a single server-scoped join, invalidate `desiredConfigRevision` when `recordAgentTraffic` crosses quota, and move `.srs` binary rule-sets out of PostgreSQL Base64 columns into content-addressed artifact storage.
2. **Decouple subscriber churn from full `sing-box` restarts:** Move probation checks off the core command loop, replace `SecretRedactor`'s linear scan and permanent latch with an active-set Aho-Corasick automaton, and evaluate connection-preserving credential updates so single-user changes do not drop active sessions across the server.
3. **Unified background maintenance & retention:** Export `scheduled()` in `app/src/server.ts` (and an optional in-process ticker for single-container Node), add certificate renewal/expiry reconciliation to maintenance sweeps, remove global table scans from hot ingestion paths, add retention/partitioning for `traffic_record`, `access_log`, and audit/token tables, and add native `sing-box` subscription output alongside honest `deviceLimit` disclosure or enforcement.
