## Parallel work and integration boundaries

- Start tasks 01, 02 and 04 independently. Use separate worktrees only when implementing concurrently. Task 03 follows the shell and ordered membership contract.
- Assign one writer for group and node persistence at each stage. Land task 02 before integrating task 06 so the second change can reuse the group write boundary. Allocate migrations in merge order and regenerate generated files from the merged sources.
- Task 05 can begin with accounting fixtures while task 04 builds the lifecycle adapter. Coordinate the runtime-instance identity and probation contract before the two changes touch the apply path. Merge the relevant accounting capability before enabling independent agent upgrades on metered servers.
- Agree on task 07's typed contracts and shared fixtures before wiring the control plane and Rust agent in parallel. Task 08 owns rollout transitions and probe outcomes. Task 09 consumes those interfaces and can prepare view states against fixtures while task 08 is in flight.
- Keep native systemd and managed networking activation independently gated. Stage the implementation with compatible agents and an additive control plane. Keep transport forwarders and multiple live runtime units deferred.

## Handoff after context compression

1. Check the current branch, worktree and working diff. Confirm the reviewed design still matches the blob above. Existing unrelated changes belong to their owners.
2. Begin with task 01 if working sequentially. In parallel, tasks 02 and 04 are the other starting points. Follow each task's dependencies before enabling its behavior.
3. Read the relevant development guides before editing. Load the repository's Drizzle skill before inspecting schema or migration code. Record assumptions and the smallest acceptance scenario for the selected task.
4. Hand off each task with its changed paths, checks and results, unresolved runtime gates, and any downstream interface changes. Use disposable databases and agents. Run the relevant app and agent checks and regenerate tracked outputs through the documented workflows.
