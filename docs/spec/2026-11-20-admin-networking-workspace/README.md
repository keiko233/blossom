# Admin networking workspace

Proposed for the admin console, managed sing-box configuration, and compatibility with existing subscriptions and agents.

Blossom will organize administration around servers, network connections, and access. A server owns its listeners and egress. Networking connects those resources and defines how traffic moves between them. Access holds subscription distribution and entitlements. Each server runs one agent. The first networking release manages one sing-box instance per server and reserves a versioned contract for additional runtimes.

## Group membership and subscription order

Place the editor in **Access → Groups**. Use dnd kit with two independently scrolling columns and a fixed group header and save bar.

| Column              | Behavior                                                                                                                                                                               |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Available entrances | Search unselected subscriber inbounds by name or server and filter by protocol and readiness. Show each public entrance and a concise path summary when it forwards to another server. |
| Selected entrances  | Show the draft membership in subscription order. Drag to insert, reorder or remove. Show pending and disabled members with their publication status and removal controls.              |

Dragging changes the draft. Save commits the complete ordered membership. Provide keyboard and pointer drag, explicit Add, Remove, Move up and Move down controls, localized announcements, and a drop target for an empty destination. Cancel restores the pre-drag order. Filters affect only the available column, so every selected row remains visible while sorting. Stack the columns on narrow layouts and keep all actions usable without dragging. Preview the effective subscription after eligibility and publication checks. [dnd kit sortable state](https://dndkit.com/react/guides/sortable-state-management/)

Membership identifies the stable subscriber entrance, never a server or its downstream hop. If A accepts subscribers and B provides egress, select A's subscriber ingress and export A's public address, port and client protocol. B's peer ingress and egress appear in server and topology views and are ineligible for group membership. If B independently exposes a subscriber ingress, that separate entrance is eligible. A future transport relay follows the same rule: the logical subscriber entrance retains a stable ID and its public endpoint belongs to A even when authorization terminates on B.

Store position per existing group-to-node membership and use a group revision for optimistic concurrency. Backfill a deterministic order with stable ID as the final tie-breaker. Route all membership writers through one atomic command that validates distinct subscriber entrance IDs, updates positions, and preserves existing publish-gate behavior for membership changes on both database drivers. Compatibility writers without positions retain surviving order and append additions deterministically. Reordering identical membership changes client output only and must not trigger agent apply or a publish-gate record.

The membership command atomically updates the revision, ordered rows and any required publish-gate change and server sequence bumps. Use a row lock and transaction on node-postgres and a revision-guarded data-modifying CTE on neon-http. Use a write plan that updates each membership row at most once, with distinct removals, retained updates and new inserts. Backfill positions before enforcing uniqueness and handle intermediate position swaps without collisions. Update every compatibility writer to participate in the same revision contract, including node deletion that cascades into memberships, group deletion and imports where applicable. Choose the dnd kit React integration using the supported React Compiler build and keyboard test.

For a plan spanning several groups, traverse its groups by group sort order and then stable group ID. Traverse each group by member position and stable entrance ID. Deduplicate by entrance ID using its first occurrence. Construct ranks from current authorized group membership. Membership snapshots used by the publish gate do not supply ordering. Apply those ranks only to the publish-gated visible set and preserve it through client rendering. A denied, disabled, or pending entrance cannot reappear through sorting. Keep the external subscription URL and client schema. Within a client format, preserve synthetic entries and policy expansion semantics while ordering exported entrances and generated lists that enumerate them.

Accept when drag and keyboard operations produce the same saved order, overlapping groups deduplicate deterministically, reorder-only saves produce no agent revision, stale edits return a conflict, and A alone appears in the exported configuration despite its B egress. Verify behavior for previously published entries, pending additions, disabled members and empty groups.

## Domain model and v1 protocol scope

| Resource              | Ownership and behavior                                                                                                                                                                                                                     |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Subscriber inbound    | Existing node identity and settings. Preserves plan/group eligibility, subscription credentials, certificate bindings and traffic attribution. Its stable runtime tag remains unchanged.                                                   |
| Peer inbound          | Server-owned listener with explicit bind and advertised peer address, TLS server name and managed certificate. Receives dedicated link identities. It is excluded from subscription exports, subscriber deployment IDs and billable usage. |
| Outbound              | Server-owned. Includes direct egress and one generated peer outbound per link. Each managed object has an immutable runtime tag derived from identity.                                                                                     |
| Link                  | Directed relation from a source server's outbound to a destination server's peer inbound. Owns per-link credential generations and configuration references. Several callers may share a listener with independent credentials.            |
| Server routing policy | Ordered rules scoped to inbound identities, reusable versioned rule-set references and explicit fallback behavior. The policy owns routes and links own connection details.                                                                |
| Client rules          | Existing Clash rules and evaluation order, under Access.                                                                                                                                                                                   |

Start with Trojan and VLESS over TCP with conventional TLS, plus direct egress. A named direct profile may select an available egress interface and IP family using validated sing-box dial fields. Keep the existing built-in direct outbound as the legacy default. Provide an adapter per supported protocol profile that validates both sides and emits the destination listener's authentication entry and source outbound from the same revision. Derive the dial endpoint from the peer's advertised address and port, and TLS verification from its explicit server name and trusted certificate chain. Keep advertised addresses separate from listen addresses and subscription addresses. Permit custom display names without changing runtime tags. Reserve listener ports in a shared claim table keyed by server and port. Backfill subscriber listener claims and update every UI and compatibility writer atomically on both drivers. Keep host listener inspection separate. Reserve existing and agent-owned tags. Show dependent rules and links before changing or deleting referenced resources. Compatible updates use the staged workflow. Require teardown before deleting a referenced resource or replacing an incompatible listener profile. New protocols, transport profiles, UDP forwarding, outbound groups, custom external peers and L3 endpoints require their own capability and lifecycle acceptance before exposure.

All subscriber writers share the topology and publication write boundary. Route the admin create, update and delete server functions in nodes.ts, the create, update and delete MCP tools in mcp-tools.ts, and any importer or cascade affecting these resources through that boundary. Reject a move, delete, disable or policy-relevant structural change to a referenced subscriber ingress unless that change is part of a staged topology update. Enforce active rollout claims on structural writes, while credential rotations and entitlement revocations remain available. Any graph-changing write compares and bumps the topology generation. For staged subscriber changes, only the stage-advance command writes subscriber rows. Make the compare-and-swap, node and membership writes as applicable, stage pointer, sequence bumps, publish-gate record and previous snapshot atomic on both drivers. Use a single data-modifying statement on neon-http. Apply the same contract to compensating writes.

## Networking workflow and routing

Topology renders managed servers with directed links, including isolated servers, and an equivalent searchable Links table. Use selection and explicit actions for edits. Dragging only repositions cards. Select a link for its endpoints, last applied revisions, and reconciliation details. Create a link by choosing a source server and destination peer inbound, or create a peer inbound as part of the draft. Link creation leaves existing traffic policy intact. Routing is a separate, server-scoped editor with ordered rules and a preview of affected ingress. A dry run produces a redacted per-server diff and shows dependencies, fallback behavior and expected process interruptions.

For example, an operator adds a peer inbound on B, creates a link from A, then gives a subscriber inbound on A a catch-all rule targeting that link. The peer ingress on B has its own egress policy. New peer ingress rejects unmatched traffic until a policy is configured. Existing subscriber ingress keeps its migrated fallback. Use ordered terminal actions with explicit direct, peer and reject targets. A link going down keeps the configured route in place and surfaces a degraded state. Any alternative egress must be explicitly authorized in a later routing profile. A catch-all is scoped to selected inbounds. Each managed peer outbound limits the forwarded network to TCP. A catch-all emits a TCP route followed by an ingress-scoped reject for remaining traffic, including UDP and QUIC. A selective peer rule rejects unsupported traffic matching that rule before later rules can route it. Show the effect on UDP DNS and allow explicit policy for destinations outside the match.

Destination address fields are ORed within their group, as are ports. Match groups are ANDed. Rule sets follow native sing-box expansion, including default-rule merging and OR between referenced sets. Defer logical and inverted rules. Use ingress-scoped nonterminal sniff and resolve actions where selected, before terminal route and reject actions. Rules for destination IP when the original request carries a hostname require an explicit compatible resolution policy. Explain rule precedence, warn about shadowing and reject rules with unresolved references. GeoIP and Geosite are rule-set presets with pinned versions, provenance and integrity, using owned rule-set assets staged by the agent. Keep the last working asset and configuration together. The control plane imports from a curated source catalog and serves bounded immutable content to authorized agents through the snapshot. The agent checks size and content hash, then assigns its own local path through a tag-to-artifact binding. Strip control-plane rule-set paths and URLs. Retain the files used by both candidate and last-known-good configurations and validate SRS format compatibility with the target binary. Include encoding overhead and existing certificate material in the snapshot size budget. Reject over-budget drafts before activation and defer larger assets to a separately versioned delivery mechanism. Block arbitrary URLs and filesystem paths. Validate rule and asset formats against the supported runtime. [sing-box route](https://sing-box.sagernet.org/configuration/route/) · [Route rules](https://sing-box.sagernet.org/configuration/route/rule/) · [Rule actions](https://sing-box.sagernet.org/configuration/route/rule_action/) · [Migration guide](https://sing-box.sagernet.org/migration/) · [Dial fields](https://sing-box.sagernet.org/configuration/shared/dial/) · [Rule-set formats](https://sing-box.sagernet.org/configuration/rule-set/source-format/)

Build a conservative dependency graph at inbound granularity. Add an edge for every possible managed forwarding target of each ingress, including fallbacks. Reject cycles and self-links in the launch scope. During rollout validate coexistence of active and candidate edges. Stage transitions that require removing an old edge before enabling a new one. Scope the check to managed forwarding and surface that scope in validation. Separate peer dial DNS from destination resolution for policy matching. Set an explicit outbound domain_resolver for peer hostnames and bootstrap it through direct egress. For a GeoIP rule on A, use A’s selected resolver and show the fallback when resolution yields no usable address. Use direct DNS and asset acquisition paths so bootstrapping cannot depend on the link being commissioned. Check every intermediate old/new policy combination against the managed graph and explain any required break-before-make operation.

### Example policy

| Server and ingress     | Match                                  | Action                               |
| ---------------------- | -------------------------------------- | ------------------------------------ |
| A, subscriber ingress  | Destination in a pinned country IP set | Route through the peer outbound to B |
| A, subscriber ingress  | All remaining supported traffic        | Direct                               |
| B, peer ingress from A | All supported traffic                  | Direct                               |
| B, peer ingress from A | Everything else                        | Reject                               |

For full forwarding, replace A's two rows with a catch-all to B for supported traffic and reject the remainder. Render the effective configuration in the inspector in evaluation order, including inherited reject rules and generated fallback rules. The preview shows what the compiler will emit and an illustrative match trace for supplied destination metadata. Live reachability comes from agent results.

## Applying changes

Keep drafts separate from desired state. Save validates the schema and records a draft version. Apply compares the expected active and draft versions and records immutable inputs, affected servers, ordered stages and audit metadata in an atomic SQL change. Use transactions on node-postgres and equivalent single-statement CTE boundaries on neon-http. Store a versioned draft, per-server applied and desired stage references, immutable managed configuration versions, credential references and a rollout journal. Reserve the affected server rows with a unique active rollout claim and acquire claims in stable server ID order. Drafts may overlap. Apply must revalidate the graph against the latest active and reserved transitions before claiming servers. Disjoint rollouts may proceed concurrently after graph validation. Serialize validation and claim creation at the topology generation boundary so two individually safe changes cannot jointly create a cycle. The reconciler must resume from persistent stage state on reconnect, duplicate messages or process restart. Persist peer inbounds, listener claims, outbounds, links, credential generations, policy versions, rule-set assets, rollout stages and per-server stage pointers. Managed inputs reach the on-demand compiler only through the current per-server pointer. Advance it atomically with a desired sequence bump and the minimum sequence and managed-state fingerprint for that stage. Read the sequence and pointer coherently and load the immutable inputs they reference. Include the managed version and artifacts in the desired digest and cache identity, invalidate on stage advance, and retain existing live-input expiry bounds.

Fence graph validation with a singleton topology generation. Read the graph and its generation from one consistent view. Every active edge, reservation or release changes that generation. Apply claims and inserts the rollout only if a compare-and-swap on that generation succeeds in the same transaction or CTE. A conflict repeats graph validation. Hash stage intent before dynamic admission and zero-user pruning. Include structural subscriber ingress and policy, peer generations and artifact references. Hash the materialized config separately, including dynamic users and certificates. A zero-user ingress may be absent from the materialized config while its policy remains staged. Validate the materialization against its intent before associating the full identifier with that stage.

Record identifiers issued for each stage with a verified managed-state fingerprint including required presences and removals. An authenticated report proves a stage when it names an issued identifier at or above the stage sequence with the same managed fingerprint. The agent reports applied after durable commit and probation. The session fences the report write, and reconnect status can prove the previously committed identifier. Subscriber access, expiry and certificate renewal can change the full identifier while preserving stage equivalence. If a material dependency invalidates the stage fingerprint, issue a new attempt and invalidate the affected probe. Emergency disable pauses affected stages and preserves immediate subscription withdrawal.

Advance stages with a database compare-and-swap on rollout ID and ordinal. Use v2 apply and status handlers plus audited admin actions on all deployment targets, including the existing handler in Cloudflare's AgentSessionDO. Provide an authenticated, bounded maintenance sweep for operator scheduling. Expired stages surface as stalled with their last confirmed state and a Retry action. A timeout cannot prove an apply or authorize cleanup. Notifications are best effort.

After commit, notify the newly activated server through the existing per-server notification path, including cross-Durable-Object delivery. Reconcile deadlines from any participating heartbeat and the bounded maintenance entry point. Reads derive the stalled status from the persisted deadline even with every agent offline. Keep claims whose release depends on unconfirmed state. A required autonomous recovery schedule is a deployment prerequisite only if the deployment promises unattended timeout processing.

An authenticated failure for the current issued stage, or an audited Abort, fences the candidate attempt and atomically advances the desired pointer to the last confirmed compatible managed version with a new sequence. Persist the failure reason and recovery target in the same write. Compile the restored version with current subscriber credentials and entitlements, so a rejected networking candidate cannot keep blocking revocations or later subscriber changes. An abort can race with an apply in progress. Treat the candidate as possibly serving until the recovery version is confirmed. Ignore stale replies for rollout advancement and hold dependency claims until recovery proves which routes and credentials remain active. Earlier confirmed receiver admissions stay available until every dependent sender is confirmed safe. Clean them up through the normal reverse-order workflow. If the failed stage also committed a subscriber structural change, compensate it atomically through the same node write and publish-gate path before serving the recovery snapshot. Preserve newer entitlement changes. Verify data-plane revocation after a failed stage and publication of a new eligible subscriber after abort recovery.

1. Stage the listener, credential and egress policy on B. Wait for proof of the committed receiver stage.
2. Stage the sender outbound on A. Use an agent-owned authenticated loopback ingress on A to probe that outbound, with a fixed agent-owned responder on B. Allow the probe only from the exact peer identity to the responder's fixed endpoint, ahead of the peer default reject. Restrict the request to a planned link and stage ID and bind the result to the applied endpoint generations and expiry. A successful probe establishes peer-path health independently from subscriber destination policy.
3. Apply the routing policy on A, then confirm its committed stage. Track pending, stalled, failed and applied state independently from current peer health. Stale or failed health alerts without changing routes.
   Use a capability-gated v2 probe request and result with probe ID, rollout and stage IDs, source and destination generations, an expiry and a bounded outcome. Persist results idempotently and confirm only an authenticated source result for the current task. The agent owns the responder and authenticates the probe independently from subscriber credentials. Ensure data-plane traffic cannot access agent management or stats endpoints, including via resolved addresses. The only probe exception is scoped to the exact stage and peer principal. Keep endpoint details local, and block activation if process isolation or the compiled policy cannot enforce that boundary.

4. To remove or roll back a link, first move source traffic away and confirm the source revision, then remove the source outbound and finally the destination admission. Credential rotation adds new receiver admission, switches and verifies the sender, then removes the old receiver admission. Connection changes that cannot coexist require a maintenance operation with explicit interruption. Keep old immutable inputs and credential generations until dependent stages are retired.

Reuse existing config fetch, compile, certificate injection, check, probation and last-known-good behavior. Gate managed networking by explicit agent capability plus validated sing-box version and adapter constraints. Block activation when an affected agent is unsupported or its state is unknown. Reject control-plane downgrades below supported versions while managed state is retained. Losing capability after an external downgrade blocks further apply and requires a compatible runtime before resuming or draining. Use per-server deterministic rendering with on-wire secrets only where that agent needs them. Use the existing publish gate under these mutation rules.

| Mutation                                                  | Effect on subscription publication                              |
| --------------------------------------------------------- | --------------------------------------------------------------- |
| Peer listener, outbound or link create, update or removal | Managed desired state and link readiness only                   |
| Peer credential rotation                                  | Managed desired state and link readiness only                   |
| Server routing and rule-set changes                       | Managed desired state only                                      |
| Subscriber inbound create, enable or config update        | Existing node change recording at the subscriber mutation stage |
| Entitlement revocation and server disable                 | Existing change recording and immediate withdrawal              |

A mandatory peer path is a prerequisite to releasing the subscriber mutation stage. Existing node change recording then gates subscription publication on the subscriber stage's sequence. This design introduces no publish-gate change kind. Adopt the table in Architecture when implementing networking, and update the AGENTS.md restatement if its criteria change.

Peer credentials are encrypted at rest using a dedicated purpose and key context. Preview, audits, errors and browser payloads contain identifiers and redacted differences. Sanitize config-check failures and probe errors before relaying them. Store credential references in drafts and rollout stages, and decrypt the necessary generations only during scoped rendering. Protect staged agent artifacts at rest and retain the current certificate and stats trust boundaries. A host receives credentials only for its own peer relationships. Keep all editor writes behind TanStack Start admin server functions with `ensureAdmin()` and `adminAudit`. Give expected editor and rollout failures stable result codes for Paraglide in English and Simplified Chinese. Preserve per-server agent authorization and current MCP contracts during migration. Treat peer ingress accounting as infrastructure telemetry. Attribute subscriber traffic at the entry server once and keep peer user identities outside the subscriber identity namespace, including malformed and replayed reports. An offline receiver can retain old admission in last-known-good state. Show revocation as pending until confirmed and surface the host isolation path for urgent revocation.

## Extension for transport forwarding runtimes

Reserve transport forwarding as a separate path kind alongside sing-box routing. A sing-box route selects an outbound using protocol-aware policy. A transport forwarder relays a listener to a configured backend and may leave TLS and subscriber authentication at that backend. For the future A-to-B relay, keep A as the public entrance and model B's backend listener and credential termination explicitly. Publish only after both the forwarding listener and required backend are confirmed through a dedicated compatibility flow. Count subscription traffic once at the authentication point. Keep relay byte counts as infrastructure telemetry.

Keep the canonical topology and listener claims independent of the process runtime. Scope deployment units by server ID and stable unit ID. Give each unit a versioned runtime kind, typed configuration, listener claims, dependency IDs, content digest and scoped artifact references. A unit may own one runtime process and several listeners. Reserve capabilities for runtime kind, adapter schema version, installed binary or module versions, and supported forwarding modes. Select adapters by explicit capability agreement. Reserve per-unit desired and applied revisions, health, validation and failure status in the agent contract.

During the first release use a single sing-box unit internally and translate it to the existing v3 snapshot for compatible legacy configurations. Put any multi-unit wire format behind a separately negotiated v2 capability and use a discriminated, versioned payload. Old agents on legacy servers continue receiving their existing snapshot. Reject an unsupported required unit before applying any dependent changes, and retain the previous working deployment. Lease fencing, artifact staging, validation, probation, dependency ordering and rollback apply to each affected unit, with readiness for the server version only after all required units commit. The agent reconciles each managed unit through the deployment’s process backend. Keep port ownership shared across runtime kinds. Accept only agent-supported binaries, locally assigned paths and typed options. Preserve least privilege and the current artifact and credential trust model.

Caddy, NGINX and dedicated forwarding engines are deferred. NGINX stream and a Caddy build with a compatible Layer 4 module are candidates. Benchmark against the sing-box baseline before choosing a fast path, using throughput, concurrent connections, CPU cost, tail latency and reload disruption. Gate later support on end-to-end tests for protocol compatibility, TLS ownership, authentication, correct client export and traffic attribution. ## Independent service lifecycle

Today the native installer registers the agent in systemd. The agent still owns sing-box as a child through processkit, and agent shutdown stops the child. Use systemd for native Linux. Keep rollout and rollback logic independent of the process backend. Docker may use a separately supervised runtime through an established and documented container deployment, with the existing processkit mode as its compatibility path. Give the agent and each managed runtime independent service units and cgroups. The agent owns desired state, validation and rollout decisions. Systemd owns process start, restart policy, stop and observation. Install fixed units with a dedicated installer or package. Do not couple the runtime unit to agent restarts or failures through PartOf or BindsTo. Agent shutdown releases its control connection and local observers while the runtime keeps serving. For externally supervised deployments, a fresh agent adopts the active unit after verifying its identity and the locally committed generation. An installation can start serving that generation before the agent can reach the control plane. [Current process manager](../../../server-agent/src/process.rs) · [Native installer](../../../app/src/lib/agent-installer-template.sh) · [systemd.unit](https://www.freedesktop.org/software/systemd/man/249/systemd.unit.html)

Keep the service operations behind a local runtime adapter with inspect, start, stop, reload and restart. Prefer typed systemd D-Bus calls via zbus. Evaluate the generated bindings in zbus_systemd against the supported distro matrix, Rust toolchain and musl release build before choosing a dependency. Subscribe to job completion and re-read the unit state after completion or bus reconnect. Keep unit names, executable selection and filesystem paths local. Use a narrow authorization boundary for lifecycle operations on the installed units. The agent identity cannot install units, manage arbitrary services or run shell commands through this interface. Any admin PTY must use an identity without service-control rights. Preserve bounded and redacted log streaming using a scoped log source for managed units and distinguish journal gaps. [zbus](https://docs.rs/zbus/latest/zbus/) · [zbus_systemd](https://docs.rs/zbus_systemd/latest/zbus_systemd/)

Install a small local privileged service-control boundary with fixed operation and service identities, using the systemd adapter inside it on native Linux. Authenticate the local caller and keep paths, executable identities and unit definitions owned by the installer. The unprivileged agent stages downloads. The privileged installer side verifies release provenance and digest against trusted metadata, copies into a protected staging location and promotes the immutable release. Keep rollback control outside the candidate binary, with a persisted attempt limit and local readiness deadline that works offline. Run any PTY through a separate unprivileged service identity without access to control sockets, protected artifacts or secrets. Source runtime logs from a dedicated bounded stream with rotation and redaction, without granting general journal access.

The current native unit disables agent self-update and uses root-owned binaries outside the agent’s writable state directory. Runtime binary replacement also requires installer-side authority in this layout. Require an operator installer rerun or package upgrade to install the new units, identities, permissions and pinned release verification key. Both agent and sing-box updates on native hosts use the same promoter. Its trust root is a release-signing public key installed by the operator-approved package or installer. Verify the signed manifest independently of the agent, including component, platform, version and artifact digest. Promote only service binaries executed under their dedicated non-root identities. The candidate cannot replace the privileged helper, unit definitions or trust key. Upgrade those only through the operator-controlled installation path.

Track independent agent and runtime release targets. In an externally supervised deployment, an agent update changes only the agent unit and leaves the serving runtime configuration and process intact. Persist update progress before restarting. Use a locally installed, bounded rollback mechanism that can restore the previous agent release if the candidate fails before it can report readiness. Stage binaries and committed configuration generations separately per runtime. A runtime update validates the candidate binary against the serving config, explicitly selects the deployment method and rolls back using the previous verified binary and config if apply fails. In the UI show which process will restart and the expected traffic impact.

Distinguish configuration reload, process restart and connection-preserving binary handoff in capabilities and status. For sing-box configuration changes, preflight and stage a candidate, attempt native reload only on qualified versions and profiles, then verify effective generation and data-path readiness before probation and commit. SIGHUP delivery or completion of a systemd job alone does not prove configuration application or survival of existing connections. Use synchronous reload confirmation or an explicit runtime observation and probe. When these are unavailable, use a controlled restart and show the interruption. Binary upgrades default to restart. Claim seamless reload or binary handoff only after tests verify listener ownership transfer, new connection availability and survival or drain of existing sessions. [systemd.service reload semantics](https://www.freedesktop.org/software/systemd/man/254/systemd.service.html)

Expose typed trial-start, commit and rollback operations for a specific managed generation as well as ordinary service lifecycle operations. A one-shot, durable trial authorization binds the candidate to the next service invocation. Consume it before starting the candidate. Any later invocation boots the committed generation unless explicitly authorized for another trial. For in-process reload, keep the committed boot selection until local readiness and probation prove the candidate. Reject commit if the observed invocation changed during probation. Identify systemd invocations with InvocationID. For s6, use boot ID, PID and process start time verified together. Run the data plane under its own service identity, with read-only access to exactly its staged or committed artifacts. The agent and other services receive no extra private-key access through that identity. A repeatable failure to establish local agent readiness triggers bounded rollback. Local readiness includes state compatibility, service reconciliation and an operational control loop. When online require a successful authenticated protocol exchange before confirming the new release. While offline retain the previous release and mark confirmation pending.

Persist a local deployment journal linking the serving and candidate generations, their artifacts and the expected systemd operation. On agent restart or host reboot, reconcile an interrupted operation against observed service state. Boot from the last-known-good generation until an unconfirmed candidate can be verified or rolled back. Keep disable intent durable and prevent a disabled runtime from resurrecting serving listeners after boot or restart. Preserve subscription publication fencing and reconnect the stats stream using the durable checkpoint and existing report deduplication. Test attribution during agent downtime and report any unobservable traffic window. If a local temporary sing-box log override can expire while the agent is unavailable, restore it through a local supervised timer or withhold that capability until offline expiry is supported.

Give the runtime an independent boot selector. Start only the committed generation, including its artifacts and durable disable state, before either the agent or the control plane is available. Candidate state lives separately. If probation is interrupted, the next startup restores the committed generation, and the reconciler verifies the running generation before reporting it applied. A disabled installation opens no serving listeners until an authenticated enablement commits.

Persist the accounting checkpoint keyed by a supervisor-provided runtime instance identity that survives agent restart and changes on runtime replacement. Atomically journal the accounted connection counters, finalised connection IDs and stable outbox report IDs at the same commit boundary, including batches generated immediately before a crash. Resume a matching checkpoint before processing cumulative counters. If the checkpoint is missing or damaged for a previously serving instance, baseline the initial live and closed snapshots and expose the unobservable window, with no historical recharge. Distinguish that case from a provably new runtime instance. Test crash before and after checkpoint commit, lost acknowledgement and closed connection replay. Decode and validate the inbound field against the supported sing-box protocol version and filter peer and probe events from billable accumulation using committed inbound classification and the subscriber identity codec.

On native Linux use the host systemd manager. For Docker, use an established, documented deployment profile that fits the supported hosts and security model, if one is available. Reuse an upstream systemd container profile only where the deployment already provides scoped cgroup delegation. Otherwise consider s6-overlay as the single alternate external supervisor. Its upstream project documents PID 1, independently supervised services and container shutdown. Use that integration as published and keep any Blossom adapter limited to service control and observation. Avoid custom cgroup plumbing, privileged container setups and a Blossom-owned supervisor. [systemd container interface](https://systemd.io/CONTAINER_INTERFACE/) · [s6-overlay](https://github.com/just-containers/s6-overlay)

If no established Docker profile fits with a small adapter, ship Docker with processkit only. Keep that mode to one agent-owned sing-box child and report its limits explicitly. Upgrading or restarting the agent also restarts sing-box in this mode. External supervision and multi-runtime support remain unavailable in that Docker profile. Choose the process backend explicitly at deployment. Never switch supervisors automatically on failure.

An external supervisor keeps the runtime alive during in-place agent upgrades. Require durable counters and report-batch checkpoints keyed by runtime instance before enabling independent restarts for metered ingress. Replacing the Docker container restarts all services inside it and is a maintenance operation. Native migration preflights the installed units, transfers listener ownership once, and preserves enrollment and last-known-good state. Retire native child-process supervision after the migration window. Docker processkit remains supported while it is the shipped Docker backend.

Rely on the selected project's published platform support and deployment instructions. Limit Blossom verification to its integration contract using the normal lifecycle suite for each shipped profile. Check configuration apply, rollback, durable disable and the documented restart behavior. For any profile advertising independent upgrades, verify that one established flow survives an agent restart with no duplicate traffic charge.

## Migration and release gates

1. **Shell and redirects.** Introduce the rail, contextual sidebars and canonical routes. Redirect old server URLs with tab and selection preserved, and old node detail URLs via an authorized lookup of the owning server. Give the old Nodes index a server-selection destination. Redirect old admin plans, subscriptions, redeem details, groups, certificates and operations links to their new equivalents, preserving resource IDs and allowlisted search parameters. For the old mixed-scope rules index, land on server routing with a visible link to client rules. Put redirects behind the existing admin guard. Keep subscription URLs, agent endpoints and MCP identifiers stable.
2. **Inbounds and access.** Ship the ordered group editor and migrate existing membership. Use the existing node storage as subscriber-inbound backing during the first release. Compare old and new config and subscription output with sanitized fixtures, preserving tags, credentials, bindings, rule order and eligibility. Preserve legacy global server rules as an ordered reject prelude over subscriber inbounds. Exclude new peer listeners from that inherited scope. For a legacy rule with scope `both`, retain one row and its compatibility write semantics. Edit it once in the global server reject layer with both effects visible. Access shows a read-only projection linking to that editor. Detaching those effects is an explicit migration. Evaluate the global subscriber reject layer before local policies. Preserve the direct fallback for existing subscriber inbounds until an operator changes it. Keep unsupported legacy rules readable in their original form and require a validated conversion before editing them through the new policy editor.
3. **Service lifecycle.** Ship the native systemd cutover with one sing-box runtime. Select the Docker profile from established deployment options or retain processkit. Retire native child-process supervision after the migration window.
4. **Managed networking.** Ship additive peer, outbound, policy and rollout persistence behind a feature gate. First release direct and managed link topology, routing and rule-set presets together for supported agents. Canary with A and B, opt in additional servers after validation, and disable further activation on regression. Before reverting to binaries that cannot carry peer state, drain and remove managed routes and links through the rollout workflow. Additive data stays available to resume or investigate.
5. **Cleanup.** Retire redundant node UI and the proxy route parent after redirects and content parity are verified. Retain external compatibility contracts on their own lifecycle.

## Implementation boundaries

The compiler in [singbox.ts](../../../app/src/orpc/proxy/singbox.ts) currently emits a single direct outbound. Extend the shared [desired-state builder](../../../app/src/orpc/proxy/agent-desired-state.ts) used by both transports. Keep subscriber deployment IDs derived from materialized subscriber inbounds. Keep legacy node TLS bindings and deployment reports. Add a versioned managed-artifact extension for capable agents with runtime tag, direction, owner kind and ID, material generation and digest. Bind the receiver's certificate and key to its inbound tag and any sender public trust artifact to the exact outbound tag. Report peer certificate deployment by peer binding identity independently of subscriber deployment IDs. Strip inline TLS material, trust overrides, client certificate and key fields, and paths from base outbounds. Use system trust and hostname verification for public peers. For a self-signed peer, mount the approved public certificate on the sender through its validated binding and verify server name and validity. Stage old and new trust before changing the receiver certificate, re-probe and then retire the old trust. Receiver private keys stay scoped to the receiver. Reject insecure overrides. Test the extension through shared contract fixtures and Rust, and regenerate OpenAPI for any HTTP surface change. [sing-box TLS](https://sing-box.sagernet.org/configuration/shared/tls/)

Digest the routing policy, TLS bindings and asset content together with the rendered configuration. Omit listeners with no valid admission entries. Intersect route scopes with materialized listeners and drop rules with an empty intersection to avoid turning an empty scope into a global match. Handle missing or expired TLS material before materializing a peer listener. Extend agent credential redaction to peer inbound and outbound fields before any candidate validation or child process logging, including rollback artifacts and candidate generations. Keep credentials registered while their associated process or retained logs can expose them.

Encode link identities outside the subscriber account codec and filter peer ingress by the committed inbound classification before the Rust traffic accumulator. Keep the v2 traffic report contract and deduplication behavior for subscriber traffic. Control-plane ingestion should also reject peer identities. Verify accounting with bytes and report deduplication across both agents, including a peer-only server.

Managed networking launch requires v2. The legacy HTTP and v1 paths remain available for legacy servers. For an enrolled managed server, reject legacy config requests explicitly while any managed configuration remains in service or last-known-good. Prevent a silent legacy compile from replacing serving peer state.

Either add the managed artifact extension to the shared V3 output schema and regenerate its Rust type, or negotiate a separately versioned v2 document with a dedicated decoder. This proposal selects the shared V3 schema for the first single-unit artifact extension and a new negotiated document only for future multi-unit support. Require round-trip fixtures through the generated decoder. Start with caps of 512 KiB raw per rule-set and 2 MiB raw aggregate per server, with a 6 MiB serialized budget for the managed activation preview under the existing 8 MiB wire cap. Count certificate and encoding overhead. Enforce the wire cap on subsequent live compiles as well and surface an oversized desired state while retaining last-known-good.

The first implementation milestone must prove parser support in the app and validation and accounting against the repository's sing-box test binary. Record exact supported version ranges and the protocol feature matrix before enabling the capability. The protocol adapters should expose bind transport and tunneled traffic capabilities independently. An unsupported traffic class in an ingress-wide forwarding rule must receive an explicit fallback or reject action in the preview.
