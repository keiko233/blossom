## Deliberate reconciliations

- The #153 relay state machine and its tests were already byte-equivalent to
  the #156 tree, so only the later serialization, documentation, and session
  fixes were taken. No sibling migration chain was reintroduced.
- The #153 v1-disconnect change also removed `ws_connected_at` uniqueness.
  That timestamp is still the v1 telemetry/PTY routing identity, so this branch
  keeps the unique timestamp and adds the session id as the disconnect fence.
- The create form is OAuth-first, but the server-function default for callers
  that omit `enableBackupToken` remains the standalone static-token default.
  Existing servers keep their static hash until an administrator disables it.
- The approved installer catalog stays empty. The static-token default and the
  catalog are rollout decisions verified separately.
- The production UI build registers the log-policy server functions through
  the Logs panel. The temporary `server.ts` discovery import was removed after
  confirming all three function ids in the built server graph.

## Migration and generated files

`24045c2` adds one Drizzle migration generated from the merged schema. It adds
the pending-proof lane columns and drops the `NOT NULL` constraint on the
static backup token columns. It was verified on a fresh database and on a
simulated #156 database that already held a static token. The route tree was
regenerated by the UI build.

## Residual gaps

- The OAuth install/v2 runtime harness is not wired into CI and was not run;
  it needs a disposable approved-release entry whose digests match the built
  artifacts.
- No hosted Neon HTTP proxy is available here, so the integration suites ran
  on `node-postgres` only.
- No browser visual pass was performed. The app build and server-function
  registration were checked from the production outputs.
