# 03 Server workspace (worker A, Wave 2)

Goal: the server pane starts with a 44px tab bar (no tall header), Overview becomes a fast HTTP-only summary, and a new **Live** tab owns the metrics WebSocket. Requires W1 merged. Read [UI design standard](../../development/ui-design.md) first.

Worker A also owns every other file under `servers/` that is not Terminal or Logs, so it migrates their page chrome and spinners in the same pass.

## Route structure

```tsx
// $serverId/route.tsx
function RouteComponent(): React.ReactElement {
  const server = Route.useLoaderData();
  const { data: servers } = useServerList();
  const item = servers?.find((row) => row.id === server.id);
  return (
    <>
      <ServerTabBar server={server} item={item} />
      {/* Keyed so switching servers remounts the active tab and drops its state. */}
      <Fragment key={server.id}>
        <Outlet />
      </Fragment>
    </>
  );
}
```

The parent renders **no** viewport. Every child route returns its own root: `WorkspaceViewport` for document tabs (`overview`, `live`, `inbounds`, `outbounds`, `settings`, `connection`, inbound forms) or `WorkbenchViewport` for `terminal` and `logs` (workers B and C). `scrollId` is `server-${server.id}-<tab>` so a tab never inherits another tab's scroll position. Tabs have no `PageHeader` (the tab is the title); add `className="[--page-header-h:0px]"` to their `WorkspaceViewport` so a `PageToolbar` sticks at the top. Inbound create/edit form pages keep a `PageHeader` (back button, title, Save) as the direct child of their viewport.

`staticData.crumb` for `$serverId` returns the server name: change `router.tsx` to `crumb?: (match: { loaderData: unknown }) => ReactNode`, pass `match.loaderData` from `AutoBreadcrumb`, and read it with a narrowing helper. Other routes keep their zero-argument crumbs.

## Server tab bar (`server-tab-bar.tsx`)

`data-slot="server-tab-bar"`, built on `WorkspaceTabBar` (`h-11`).

```text
┌ Overview  Live ┊ Inbounds  Outbounds ┊ Logs  Terminal ┊ Connection  Settings ┈┈┈ [2 pending] ● Online ⋯ ┐
└─ 44px, border-b, nav scrolls horizontally below ~640px, right cluster never shrinks ───────────────────┘
```

- Left: `nav` (`aria-label={m.admin_proxies_servers_workspace_tabs_label()}`, `flex min-w-0 flex-1 items-stretch gap-0.5 overflow-x-auto`) of TanStack `Link`s, one per tab, with a `Separator orientation="vertical"` (`my-auto h-4`) between the four groups **Observe** (Overview, Live), **Configure** (Inbounds, Outbounds), **Operate** (Logs, Terminal), **Manage** (Connection, Settings). Keep the existing `serverTabVariants` active styling (`aria-[current=page]` underline) and add `outline-none focus-visible:ring-[3px] focus-visible:ring-ring/24 focus-visible:ring-inset` and `h-full px-3 text-sm`. The existing `data-slot="server-workspace-tabs"` becomes `server-tab-bar`.
- Right cluster (`ms-auto flex shrink-0 items-center gap-2 ps-2 pe-1`):
  1. Pending-changes badge when `item?.pendingConfigChanges > 0`: `Badge size="sm" variant="warning"` with text `m.admin_proxies_servers_pending_changes({ count })` and a `Tooltip` carrying `m.admin_proxies_servers_pending_changes_help()`. Hidden below `sm`.
  2. `ServerStatusPill`: `StatusDot` + `text-xs` label from the existing status map; the full `lastErrorMessage` stays a `title`. Label hidden below `lg`, the dot (with `aria-label`) remains.
  3. `ServerActionsMenu` (existing; render its trigger with `size="icon-sm"`), only when `item` exists. While the list is loading render a `Skeleton className="size-7"` in its place so the bar does not shift.
- `server-status.tsx`: add `ServerStatusPill`, and replace `statusDotClass` literals with `StatusDot` tones (`online→success`, `degraded|unknown→warning`, `agent_offline|runtime_error|config_error→danger`, `disabled|awaiting_installation→muted`). Keep `ServerStatusBadge` exported and unchanged in appearance for any other caller.
- Mobile (`servers/route.tsx`): the existing `md:hidden` strip becomes `Servers` toggle + `·` + selected server name + `StatusDot` (read `serverId` with `useParams({ strict: false })`). The sidebar keeps the list toggle behavior.
- Keyboard: tabs are links in DOM order; `ArrowLeft`/`ArrowRight` move focus between tabs when focus is inside the `nav` (roving, same helper style as `server-sidebar.tsx`'s `moveFocus`), `Home`/`End` jump to first/last.

## Overview tab (HTTP only, no WebSocket)

`overview.tsx` → `WorkspaceViewport` (`scrollId="server-<id>-overview"`, `[--page-header-h:0px]`) → `PageContent` → recipe R3 with a right rail from `xl`:

```tsx
<div className="3xl:grid-cols-[minmax(0,1fr)_26rem] grid min-w-0 gap-6 xl:grid-cols-[minmax(0,1fr)_22rem]">
  <aside
    data-slot="server-overview-rail"
    className="flex flex-col gap-6 xl:order-last"
  >
    <ServerIdentitySection server={server} item={item} />
    <ServerVersionsSection server={server} />
  </aside>
  <div data-slot="server-overview-main" className="flex min-w-0 flex-col gap-6">
    <ServerHistoryPanel serverId={server.id} /> {/* metric charts */}
    <TrafficTrend serverId={server.id} />
  </div>
</div>
```

Below `xl` the rail renders first (identity above charts). No bordered cards: each section is `SectionHeader` + content, separated by `border-t pt-6` inside the rail; charts sit directly on the page background in a `grid gap-6 md:grid-cols-2` (the history panel's existing 2-up logic).

- **Identity section** (`data-slot="server-identity"`): `dl` as `grid grid-cols-[7rem_minmax(0,1fr)] gap-x-3 gap-y-2 text-sm`. Rows: Address (`font-mono`, copy button), Remark (hidden when empty), Status (`StatusDot` + label), Transport (`ws`/fallback, from `transportMode`/`wsConnectedAt`), Last seen (`formatDateTime`), Pending changes (count, plus one-line `text-xs text-muted-foreground` help), Last error (`text-destructive`, shown only for `degraded`/`config_error`/`runtime_error`, as today). Data comes from the loader's `server` and the list `item`; there is no skeleton for loader data. Pending changes depends on the list query: render `Skeleton className="h-4 w-8"` for that value until `item` exists.
- **Versions section** (`data-slot="server-versions"`): two rows (Agent, sing-box) reusing `VersionItem`'s content (`v1.6.0 → desired`, `updateStateLabel` badge, failed error text) plus the **update check buttons moved out of the old live panel**: `Button size="xs" variant="outline" loading={update.isPending}` calling `checkServerUpdate({ data: { id, target } })`, disabled when the server is disabled, with the existing result text (`requested|polling|unmanaged|failed`) in a `role="status"` line. Reuse the existing `server_live_update_*` messages for the result text.
- **History and traffic**: remove their outer cards and spinners. `ServerHistoryPanel` keeps its range controls and `MetricLineChart`s; initial load renders `ChartSkeleton` ×4 in the same grid, refetch with `keepPreviousData` keeps old charts. `TrafficTrend` renders one `ChartSkeleton`. Each region has its own error line; a failed chart never hides the identity rail.
- The page must not import or render anything that opens `/api/admin/servers/*/metrics/ws` or `/stream`.

## Live tab (`live.tsx`, `/admin/servers/$serverId/live`)

`staticData.crumb: () => m.admin_server_ws_tab_live()`. Document pane (it is a short page and benefits from the sticky toolbar):

```text
WorkspaceViewport [--page-header-h:0px] scrollId="server-<id>-live"
├─ PageToolbar  (h-11, sticky top-0)
│    ● Streaming · v2        telemetry transport badge          [⏸ Pause]  [Inspect network]
└─ PageContent
     ├─ live-gauges   one bordered strip: CPU │ Memory │ Disk   (grid divide-x md:grid-cols-3)
     ├─ environment line  "systemd · host"  (text-xs text-muted-foreground)
     ├─ live-charts   grid gap-6 md:grid-cols-2   (CPU, Memory, Network rx/tx, Disk)  — the existing four MetricLineCharts
     └─ network-inspection  (SectionHeader "Network inspection"; empty until requested)
```

- **Stream state machine** (`use-live-metrics.ts`, extracted from `server-live-panel.tsx` with the same WebSocket URL, `adminMetricsServerMessageSchema` parsing, bounded window via `appendLiveSample`, exponential reconnect up to 30 s): inputs `{ serverId, enabled, paused }`. `enabled` is `liveStateOf(server) === "connected"`. The hook auto-connects on mount when enabled and not paused, closes on unmount, and closes when `paused`. Pausing keeps the frozen samples visible; resuming starts a **new** series (clears samples) so no continuity is fabricated across the gap. Phases: `idle | connecting | connected | reconnecting | paused | error`. **Recommended:** also pause automatically while `document.visibilityState === "hidden"` for more than 60 s.
- **Status text** (toolbar, `role="status"`): `Streaming`, `Connecting…`, `Reconnecting…`, `Paused`, or the server `error.message`; tone mapping via `StatusDot` (`success`, `info`+pulse, `warning`+pulse, `muted`, `danger`). Protocol `v1`/`v2` as a small `Badge`. The old `transportLabel` badge (`connected | fallback | legacy | disabled | unavailable`) moves here.
- **Not connectable** (`state !== "connected"`): no socket; render a compact `Empty` in `PageContent` with the reason (`m.server_live_fallback` etc.) and a link to the Connection tab. Toolbar controls are disabled.
- **First paint:** before the first sample arrives show skeletons (the gauge strip as `StatStripSkeleton items={3}`, `ChartSkeleton` ×4); after samples exist never show them again. A connected stream with zero samples after 5 s shows `m.server_live_no_samples()` in the chart boxes.
- **Network inspection:** unchanged behavior (`fetchInspection` HTTP mutation against `/stream?inspect=1`, `gcTime: 0`); while pending render `TableSkeleton rows={4} columns={4}`; results as two dense tables (Listeners with the `overlapsNode` flag shown as a `Badge size="sm" variant="warning"`, Interfaces) in one section separated by `border-t`; errors inline. No card.
- Gauges: percent text in `tabular-nums`, `Progress` `h-1.5`, missing values show `m.server_live_missing()`. Reuse `usageText`/`usagePercent`; move them to `lib/server-live-state.ts` with tests.

`lib/server-live-state.ts` (pure, isomorphic): `capabilityOf(server)`, `liveStateOf(server)`, `usagePercent`, `formatUsage`, `streamTone(phase)`. Tests (`server-live-state.test.ts`): each `liveStateOf` branch (disabled, ws not connected → fallback, ws connected without capability → legacy, telemetry-v1/v2 → connected), `usagePercent` null/zero/over-100, `streamTone` for every phase.

Manual QA (preview tools, light and dark, 1280 / 1920 / 2560 / 390 px):

- Opening a server shows tabs at the very top (44px) with no header above; the pane has exactly one scrollbar; the sidebar scrolls independently.
- Network panel on Overview shows **no** WebSocket; on Live it shows exactly one `/metrics/ws`, closed when navigating to another tab or server, closed on Pause.
- Switching servers resets the active tab's state; Back restores the previous tab's scroll position.
- Tab bar overflow scrolls horizontally at 390 px without hiding the actions menu.
- Server with `pendingConfigChanges > 0` shows the badge; a disabled server shows a muted dot and the Live tab shows the reason empty state.
