# Desktop-class admin UI overhaul

Proposed. A phased, parallelizable plan to turn the Blossom admin console from a stack-of-cards dashboard into a desktop-class operational workstation, with six new capabilities along the way: a top tab strip for the server workspace, a dedicated Live tab, a React Flow topology workbench, full-bleed Terminal and Logs workbenches, skeleton-first loading, and a rule-set workflow that imports from the official sing-box repositories and compiles custom rules to binary `.srs`.

This is a plan, not a description of current behavior. The permanent rules it implements are in [UI design standard](../../development/ui-design.md); read that first. Where this spec and the standard disagree, fix the standard in the same change. This spec supersedes the sentence "The server list, server header and tabs remain visible while the selected tab scrolls" in the [admin networking workspace spec](../2026-11-20-admin-networking-workspace/README.md): the server header is removed and the tabs become the top bar of the pane.

## Audit summary (what the code does today)

Checked against the source on 2026-11-26.

1. **Shell and scroll.** `(admin)/route.tsx` renders `SidebarProvider h-dvh` → `SidebarInset` → `AppShellHeader` → `admin-viewport` (`overflow-y-auto`). Workspaces use `Workspace` (`md:` grid `18rem | 1fr`), `WorkspaceSidebar`, `WorkspacePane`, `WorkspaceHeader`, `WorkspaceViewport`. `admin-viewport` stays scrollable even when a workspace fills it, so any overflow yields a second scrollbar. There is no fixed workbench pane; Terminal, Logs and Topology are document panes.
2. **Sticky header defect.** `AdminWorkspaceFrame` forces every descendant `[data-slot=page-header]` to `sticky top-0 bg-background` with a descendant selector, but 26 `<PageHeader>` call sites render inside `p-4` / `p-4 md:p-6` wrappers or inside cards. Result: gutters show scrolled content, no bottom edge, per-page alignment drift, a header escaping its card (`users/$userId.tsx`), and no stickiness in the Servers workspace. Four form pages re-declare `sticky … bg-background/80 backdrop-blur`. Details in [ui-design.md §4](../../development/ui-design.md#4-page-chrome-padding-and-sticky-headers).
3. **Server workspace.** `$serverId/route.tsx` renders `WorkspaceHeader px-4 pt-4 md:px-6 md:pt-6` containing `ServerWorkspaceHeader` (name, status badge, address, remark, pending-changes line, actions menu) and then `ServerWorkspaceTabs` (`Overview, Inbounds, Outbounds, Settings, Terminal, Logs, Connection`). That is ~110px of chrome before any content. Every tab shares one padded `WorkspaceViewport` keyed by server id.
4. **Overview opens a WebSocket.** `ServerOverviewPanel` renders `ServerLivePanel`, whose `useLiveMetrics` opens `/api/admin/servers/$id/metrics/ws` as soon as the server is `connected`; the Overview also mounts `ServerHistoryPanel` and `TrafficTrend` (two more queries, each with its own `Spinner`). The update-check buttons live in the live panel.
5. **Terminal.** `AgentTerminalPanel` is a bordered card (`rounded-xl border bg-card p-4`) with a title block, two notice boxes, and an xterm at fixed `h-[28rem]`. `XtermTerminal` already uses a `ResizeObserver` and `FitAddon`, but its container defaults to `min-h-72 rounded-lg bg-[#0b0f14] p-2` and the xterm theme colors are hard-coded. Opening requires `Confirm.call` and a `/pty/status` probe (both must be kept).
6. **Logs.** `ServerLogsPanel` is a card containing a header, several dashed notice boxes, a filter row, the full `ServerLogPolicyPanel` (576 lines, per-source cards inside a card), the viewer at fixed `h-[28rem]`, and a search panel with an inner `max-h-72 overflow-y-auto` results list. Nested scrollers and nested boxes throughout. `use-server-logs.ts`, `LogViewer` virtualization and keyboard handling are sound and are kept.
7. **Topology.** `topology.tsx` renders a `PageHeader`, a search box, a "canvas" that is really a grid of server cards (`topology-canvas.tsx`), a list section, an inspector section and a rollouts section, all as cards. `lib/networking-topology.ts` already provides the pure model (`buildTopologyList`, tones, selection) and tests. There is no graph.
8. **Loading.** 45 `<Spinner />` call sites in 39 files; `<Skeleton />` is used by one page. Several screens load in cascades (Routing editor, server Overview, Traffic page, Dashboard).
9. **Rule sets.** `managed_rule_set_asset` stores immutable rows `(rule_set_id, version)` with `format = 'binary'` (DB `CHECK`), `size_bytes BETWEEN 1 AND 524288`, `sha256 ~ ^[0-9a-f]{64}$`, `source`, `content_base64`. `importRuleSetAssetDraft` (in `query/networking-write.ts`) validates canonical base64 and the 512 KiB bound and inserts. The only UI is a dialog that uploads a `.srs` file; "presets" in `MANAGED_RULE_SET_PRESET_CATALOG` are metadata only. The agent contract (`packages/contracts/src/agent-config-v3.ts`) accepts only `format: "binary"`, and `server-agent/src/config_managed.rs` rejects any artifact whose first three bytes are not `SRS`, then runs `sing-box check` on the staged files.

## Decisions

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                        | Why                                                                                     |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| D1  | Two pane archetypes: `WorkspaceViewport` (document/table, one scroller) and `WorkbenchViewport` (fixed, tool-owned scroll). `admin-viewport` stops scrolling when a workspace fills it.                                                                                                                                                                                                         | Removes nested scrollbars structurally instead of per page.                             |
| D2  | `PageHeader` becomes an explicit sticky, full-bleed component rendered as a direct child of the viewport; `PageContent` is the only padded element; the descendant-selector side channel is deleted.                                                                                                                                                                                            | Fixes the sticky/padding defect once and identically for every route.                   |
| D3  | Server tab bar is the first element of the server pane (44px) with the status pill, pending-changes badge and actions menu inline at the right. The tall server header is deleted; identity moves to the Overview.                                                                                                                                                                              | Reclaims ~110px; the server name is already highlighted in the sidebar.                 |
| D4  | Tab order: `Overview · Live · Inbounds · Outbounds · Logs · Terminal · Connection · Settings`, grouped Observe / Configure / Operate / Manage with thin separators.                                                                                                                                                                                                                             | Daily monitoring tabs first; rarely used admin tabs last.                               |
| D5  | New `live.tsx` route owns the metrics WebSocket. Overview is HTTP-only.                                                                                                                                                                                                                                                                                                                         | Opening a server must not open a stream; Live is an explicit, pausable stream.          |
| D6  | Topology uses `@xyflow/react@13.0.3` (verified: peers `react >=18`, `react-dom >=18`; ESM only; exports `style.css`, `base.css`, `xy-theme.css`; `sideEffects: ["*.css"]`; node ≥ 20; deps `zustand`, `classcat`, `@xyflow/system`). It is rendered client-only (`ClientOnly`) with a skeleton fallback, themed through Blossom CSS variables. Layout is a pure-TS layered algorithm in `lib/`. | No `dagre`/`elkjs` bloat, deterministic and unit-testable, no SSR sizing problems.      |
| D7  | Terminal and Logs are workbenches: top bar, canvas, status bar. The log policy UI moves to a right `Sheet`. Search results are a bottom drawer below `xl` and a right split pane from `xl`.                                                                                                                                                                                                     | Eliminates nested cards/scrollers and gives the tool the full viewport.                 |
| D8  | Skeleton-first loading with eight shared skeleton components; `Spinner` only inside buttons and toolbar refresh indicators.                                                                                                                                                                                                                                                                     | See [ui-design.md §5](../../development/ui-design.md#5-loading-empty-and-error-states). |
| D9  | **Custom rule sets are compiled to binary `.srs` by a pure-TypeScript encoder** (wire format in [02](02-srs-codec.md)). No schema, contract or agent change.                                                                                                                                                                                                                                    | See the evaluation below.                                                               |
| D10 | Official import fetches **exact `.srs` files from `raw.githubusercontent.com` at an immutable commit SHA**, for exactly two allowlisted repositories, with size, magic and decompression checks; manual `.srs` upload stays.                                                                                                                                                                    | Operator convenience without opening an SSRF or supply-chain hole.                      |

### D9 evaluation: how to produce `.srs` without a CLI

| Option                                                                | Deploy-target safe                                                                                            | Contract/agent change                                                                                                                          | Verdict                                                                                                                                                                                                                                                                                                                                                                               |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A. Pure-TS encoder in `app/src/lib/srs/` (CompressionStream for zlib) | Yes: no `node:` imports, no `Buffer`; works on Node, Vercel and Workers                                       | None                                                                                                                                           | **Chosen.** The wire format was cross-checked on 2026-11-26: a prototype decoder + re-encoder reproduced the inflated payload **byte-for-byte** for four real official files (`geosite-apple`, `geosite-cn` (18,485 domain keys), `geosite-category-ads-all`, `geoip-cn` (6,201 IP ranges)), and rebuilt the domain matcher key sets from `domain`/`domain_suffix` lists identically. |
| B. Store JSON source and extend the contract to `format: "source"`    | Yes                                                                                                           | DB `CHECK`, `ManagedRuleSetFormat`, snapshot schema, agent magic check, `.json` staging path, and agent-version skew (old agents would reject) | Rejected: wide cross-cutting wire change for no operator benefit.                                                                                                                                                                                                                                                                                                                     |
| C. Shell out to `sing-box rule-set compile`                           | **No**: impossible on Workers and Vercel functions                                                            | None                                                                                                                                           | Rejected.                                                                                                                                                                                                                                                                                                                                                                             |
| D. Compile on the agent (it has `sing-box`)                           | Yes                                                                                                           | New agent protocol, digest no longer known to the control plane before rollout                                                                 | Rejected: loses the control-plane digest/size verification and offline determinism.                                                                                                                                                                                                                                                                                                   |
| E. `node:zlib` instead of `CompressionStream` inside option A         | Works on `nodejs_compat` (`wrangler.jsonc` enables it) but `maxOutputLength` support in workerd is unverified | None                                                                                                                                           | Allowed only as a server-only fallback. Prefer web streams so the codec is isomorphic (the UI can preview and offer a `.srs` download client-side).                                                                                                                                                                                                                                   |

Residual risk of option A, stated plainly: the encoder was verified against sing-box output structurally, but the final authority is `sing-box check` on the agent. Wave 3 must run the generated files through a real `sing-box rule-set decompile` and `sing-box check` (not available in the authoring environment) before the feature is considered done.

## Execution plan

### Branching and merging

- All work lands on one integration branch, `feat/desktop-ui-overhaul`, in this order: Wave 1 → Wave 2 → Wave 3. Intermediate integration states are allowed to look transitional (for example, un-migrated pages lose their sticky header until worker F migrates them) because nothing ships until Wave 3 passes.
- Every worker uses its own worktree `../blossom-<branch-suffix>` and typed branch `feat/ui-<workstream>` ([Workflow](../../development/workflow.md#worktrees-and-resource-reuse)), branches from the integration branch, and rebases onto it before opening its PR. Never share `node_modules/`, `target/` or a dev port across worktrees.
- Stage explicit paths. Never `git add .` or `-A`. Atomic, buildable commits; fold fixes into unpushed commits. Do not commit `.env.local`, tokens or build output.

## Global contracts (apply to every worker)

1. **No application code outside your file list.** If you need a change elsewhere, stop and report it in the PR description.
2. **Follow [AGENTS.md](../../../AGENTS.md)**: admin server functions call `ensureAdmin()`; every `POST` server function in `app/src/query/` carries `adminAudit(...)` (enforced by `lib/admin-audit.test.ts`); never print or commit secrets; no `useMemo`/`useCallback` by default (React Compiler is on); no `any`; `import type`; `m.some_key()` for every visible string.
3. **Layout classes come from the UI standard.** Pane archetype, bar heights (`h-11` tab bar, `h-10` workbench bar, `h-7` status bar, `min-h-12` page header) and the ban list are binding.
4. **Server vs client boundary.** Client bundles must not import `@/db`, `@blossom/database/server` or `node:*`. The SRS codec and every `lib/` module in this plan are isomorphic (no `Buffer`, no `node:`).
5. **Per-viewer preferences** (terminal font size, topology node positions, inspector collapsed state, logs search-bar state) may use `localStorage` wrapped in `try/catch`, behind a small `lib/` helper, with versioned keys `blossom.<area>.<name>.v1`. Never store secrets, tokens or session inputs.
6. **Keep behavior safety gates verbatim**: `Confirm.call` before opening a terminal, the `/pty/status` probe, log subscription audit rows, `ensureAdmin()`/`adminAudit`, same-origin WebSocket URLs.
7. **Verification for every PR** (state which ran):
   `pnpm --filter @blossom/app exec tsc --noEmit` · `pnpm fmt` · `pnpm lint` · `pnpm test` · your focused test files via `pnpm --filter @blossom/app exec vitest run <path>` · `pnpm build` (Cloudflare default) for any PR that touches routes, server functions or `styles.css`; also `pnpm --filter @blossom/app build:node` for E and W2 (codec / outbound fetch).
8. **No DOM tests exist** (`vitest.config.ts` includes only `src/**/*.test.ts` in Node). Component quality is verified by `tsc`, build and the manual QA checklist in the worker's doc; logic goes into testable `lib/` modules.
9. The PR description lists: files changed, i18n keys added (prefix and anchor), commands run with results, what was not verified, and screenshots at 1280 / 1920 / 2560 px in light and dark when UI changed (use the in-app preview tools).

## Definition of done for the whole overhaul

- [ ] `pnpm --filter @blossom/app exec tsc --noEmit`, `pnpm fmt`, `pnpm lint`, `pnpm test` pass on the integration branch; `pnpm build`, `build:node` and `build:vercel` succeed.
- [ ] Grep audits clean: no `[data-slot=page-header]` descendant selector in `admin-workspace-frame.tsx`; no `backdrop-blur` in `routes/(admin)`; no `h-[28rem]` in `routes/(admin)`; no `<Spinner` that is the sole child of a pane, card, table body or dialog body; no `rounded-2xl`/`rounded-3xl` class added in `routes/(admin)`.
- [ ] `route-tree.gen.ts` contains `/admin/servers/$serverId/live` and is committed; `en.json` and `zh-cn.json` have identical key order and counts.
- [ ] Manual QA matrix (1280×720, 1920×1080, 2560×1440, 390×844; light and dark): one scrollbar per region everywhere; Terminal, Logs and Topology have no outer scrollbar and no outer padding; opening a server does not open `/metrics/ws` until the Live tab is shown; every page header aligns with its content and stays solid when stuck.
- [ ] Terminal: confirm gate and `/pty/status` probe still run; connect, type, resize the browser, disconnect.
- [ ] Rule sets: import one official geosite and one geoip set end to end into a disposable database; create a custom set; run the generated `.srs` files through real `sing-box rule-set decompile` and `sing-box check`; roll one out to a disposable agent. Report any mismatch as a codec bug.
- [ ] `docs/development/ui-design.md`, `app.md` and `architecture.md` describe what landed; **Recommended** items that are now enforced are marked **Established**.
