Requires W1 merged. Read [UI design standard](../../development/ui-design.md) sections 1-6 first.

## Universal migration rules

1. **Chrome.** Each route's root becomes the direct content of the viewport (the `AdminWorkspaceFrame`'s `WorkspaceViewport`, or `admin-viewport` for the Dashboard): `<PageHeader>` first, then optional `<PageToolbar>`, then `<PageContent>`. Delete the outer `div className="flex flex-col gap-4 p-4 (md:p-6)"` wrappers. `PageHeader` holds `PageHeaderTitle`, an optional one-line `PageHeaderDescription` (only where it is genuinely useful; otherwise delete the paragraph), and `PageHeaderActions`. Remove `className` overrides that restyle the header (`text-2xl`, `sticky`, `backdrop-blur`, `bg-background/80`, `px-4 py-3`).
2. **Nested headers.** A `PageHeader` rendered inside a card, section or dialog (for example `access/users/$userId.tsx`) becomes `SectionHeader`.
3. **Filters and search.** The row of search/filter/bulk controls above a table becomes `PageToolbar` (sticky, `h-11`); delete bordered toolbar cards. Bulk-selection bars replace the toolbar content while rows are selected.
4. **Tables.** Use `Table variant="pane"` full width with `h-9` rows, `tabular-nums` numeric columns, `font-mono` identifiers, and responsive column hiding instead of horizontal scroll. Sorting stays in `sort-header.tsx`. Pagination (`list-pagination.tsx`) sits in a `border-t` footer row inside `PageContent`, not in a card. Remove cards around tables.
5. **Loading.** Replace every `<Spinner />` listed below with the skeleton that matches the final layout (`TableSkeleton`, `KeyValueGridSkeleton`, `FormSkeleton`, `ChartSkeleton`, `StatStripSkeleton`, `SidebarListSkeleton`, `InspectorSkeleton`). One gate per region ([query coordination](../../development/ui-design.md#query-coordination)). A `Spinner` may remain only inside `Button loading`/a toolbar refresh indicator. During polling refetches keep the previous data.
6. **Error and empty states** keep their text and retry actions but render in the same footprint as the skeleton (`Alert`/`Empty`), without the old `p-4 md:p-6` wrappers.
7. **Surfaces.** Replace `rounded-xl border bg-card p-4 shadow-xs` boxes and one-off `Card` usage with flat sections (`SectionHeader` + content, `border-t`/`border-b` separators). `Card`/`FramePanel` is acceptable only for a standalone summary object that must read as one unit (for example an issued credential). Remove emoji, decorative icons next to headings, `uppercase tracking-*` eyebrows and gradients if any exist.
8. **Strings.** Do not rewrite copy. Delete strings only when you delete the element; leave orphaned message keys in the JSON (the Wave 3 integrator prunes after checking usage).
9. **Behavior.** No change to queries, mutations, search-param schemas, audit calls or permissions. Dialogs, `Confirm.call` flows and forms keep their logic.

## New shared component: `StatStrip` (`components/app-shell/stat-strip.tsx`)

Replaces vanity KPI tiles. `StatStrip` (`data-slot="stat-strip"`): `grid divide-y border-y sm:grid-cols-2 sm:divide-x sm:divide-y-0 xl:grid-cols-5` (columns via `cva` variant `columns: 3 | 4 | 5`), no radius, no shadow, on the page background. `StatStripItem` takes `label`, `value` (rendered `text-lg font-semibold tabular-nums`), optional `detail` (`text-xs text-muted-foreground`), optional `tone` (`warning` colors the value with `text-warning-foreground`, nothing else), optional `href` (renders the whole item as a `Link`). No icons. While loading use `StatStripSkeleton`.

## Tests and verification

No new logic modules are required. If you extract view logic (for example the dashboard attention-list shaping or the settings section list), put it in `app/src/lib/` with a `*.test.ts`. Required runs:

```bash
pnpm --filter @blossom/app exec tsc --noEmit
pnpm fmt && pnpm lint && pnpm test      # includes settings-ui.test.ts and admin-audit.test.ts
pnpm build
```
